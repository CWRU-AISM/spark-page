Abstract

Changes to what a robot can see do not mean that there is a change in the problem it is trying to solve, and many language-conditioned manipulation systems struggle with this distinction. When something in a scene moves, the robot might need to execute its actions in different places, but its manipulation plan can stay the same. We propose Sequential Planning via Anchored Robotic Keypoints (Spark), which describes a task as a symbolic behavior tree that we anchor to the current 3D observations when each action is called. By verifying the plan at runtime we can recover from failures locally and anchor the objects to the scene again. We ask for a new plan only if this fails. We isolate this concept by taking a fixed plan and moving objects in the scene while executing. When displacing objects by 10 cm we were still able to complete 66.7% of trials with scene-diff verification and layered recovery, and we did not have to change the plan. Without practicing on the tasks being tested or using ground-truth object poses from the simulator during rollouts, we test our full system (with one open-weight 27B planner with 4-bit weights) on LIBERO-PRO. Under this protocol SPARK achieves a mean success of 75.1% across the 6 position and task settings and 69.7% on the held-out language and object settings. We also achieve a 68% success rate across 11 physical task-embodiment settings on 3 different robots. Our work demonstrates that for an important class of failures, the robot does not need to ask for a new plan for its task. It can be enough to update the system's view of the world.

Composing the score

SAM3 grounds the objects seen by the platform cameras. One language-model call writes the entire plan as a typed behavior tree, the score, and the robot executes it with no task-specific model training. The LIBERO-PRO results use the open-weight Qwen3.8-27B with 4-bit weights, served locally; the perception ablation and the physical robots use Gemini. Actions reference objects by label, and at execution time each label is grounded to a current 3D position. A modified instruction can invalidate the plan, while a moved object typically only makes the plan's object locations incorrect. Putting the bowl on the plate should use the same score whether the bowl started on the left or the right, because only the pixels that the label bowl refers to have moved. SPARK keeps the plan and updates what perception says about the scene.

Each skill checks a post-condition. When a check fails, up to three tiers of recovery are tried in order. Tier 1 is an in-place correction, like a small motion and a re-grasp. Tier 2 is re-perception: retract the arm 10 cm, run SAM3 again, and re-execute the same plan with updated object locations. Tier 3 asks the language model for a replacement plan, but only after the execution attempt is exhausted. Tiers 1 and 2 keep the behavior tree and need no language-model call. Five base primitives (move_to_keypoint, move_relative, grasp, release, wait) cover basic motion; over thirty registered skills implement closed-loop behaviors such as descending until a force is reached, detecting contact, and retrying locally. All skills were written with Claude Code against a typed contract and checked by the authors, and the skill registry does not change during any reported run.

In simulation, one additional language-model call suggests three prompts per object, and SAM3 confidence selects the detection. On the matched ablation this raises spatial success by 26.5 points and object success by 8.2, but lowers goal-task success by 8.4. LIBERO-PRO adds two more grounding steps. The planner chooses an uncertain pick target from numbered wrist-camera crops taken at the home pose. When a scene has multiple copies of an object, a hand-coded rule picks one from the relation in the instruction (between, next to, on, in) without asking the language model. Physical robots use one prompt per object.

On the language and object perturbations, which were not used to derive the grounding rules, SPARK averages 69.7% (object 92.4 and 77.4, goal 64.6 and 47.2, spatial 50.8 and 85.8). When retries are decided only by the robot's own grasp and scene checks and the success check runs once after execution, SPARK scores 67.5% on the same six settings.

Recovering when objects move (LIBERO-Displace)

The object slides by 0 to 10 cm over 40 simulator steps on the same seeded schedule in both conditions, and object detections update between primitives in both. The planner is not in the loop.

CaP-Bench (Robosuite)

Per-task success (%). SPARK and CaP-Agent0 use 100 trials per task; RATS uses its 50-trial skill-transfer evaluation. With the Qwen planner SPARK averages 65.1% against 68.3% for CaP-Agent0's three-model ensemble. It completes Lift in every trial, CubeRestack in 97% and Stack in 93%, reaches 77% on TwoArmLift and 30% on TwoArmHandover, and drops to 57% on Wipe and 2% on NutAssemblySquare.

Physical experiments

The same BT grammar, Gemini planning call, and SAM3 pipeline run on UR10e, Franka FR3, and a bimanual Franka setup, without task-specific model training. Nine tasks span three embodiments (eleven task-embodiment cells), 20 trials per cell, objects randomly placed and rotated per trial. All physical runs use hardware depth and single-description perception.
